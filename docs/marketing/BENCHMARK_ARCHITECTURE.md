# Public benchmark architecture

Accordo distinguishes **engineering benchmarks** (runtime correctness or performance), **agent benchmarks** (an agent/model executing a controlled build), **product benchmarks** (a buyer-relevant system property), **customer outcomes** (observed customer results), and **illustrative examples**. One may not be relabelled as another.

A public result is publishable only when its canonical record contains: question and metric; why it matters; scenario and fixture; environment; framework SHA/version; agent/model version when relevant; baseline or an explicit `none`; measurement date; methodology; limitations; reproduction path; and evidence. Missing fields mean “no public result,” not zero.

Decision-relevant dimensions are: intent-to-working-application time; first verified workflow; rule-to-enforcement time; infrastructure avoided; reusable primitive breadth; end-to-end workflow coverage; invalid-transition refusal; approval/policy enforcement; audit/trace; independent composition inspection; agent plan/build/recovery loop; package extensibility; source ownership/portability; checked-in reproducibility; and explicit non-proof. Existing benchmark protocols and fixtures remain their canonical authorities. The website links them through Product Proof and publishes no invented values or competitor numbers.
