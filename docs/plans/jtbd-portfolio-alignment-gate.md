# ExecPlan — JTBD Portfolio Alignment Gate v1

**Branch** `claude/jtbd-portfolio-alignment-gate` · **base** `docs-jtbd-phase-d-raw` at
`f14d64d` (the 600-record desired-state catalogue; **not on `main`** — PR #107 is open).

## The problem

`docs/jtbd/` now holds a 600-record desired-state catalogue. `docs/benchmarks/CRM_JTBD_MATRIX.md`
holds this repository's conservative coverage rows. `docs/strategy/EXECUTION_ROADMAP.md` holds
the milestones. Nothing connects them, and nothing stops the three from being read as one
number.

The specific failure this gate exists to prevent: **a desired job being read as a supported
job**. All 600 catalogue rows are `NOT_ASSESSED`. A reader — or an agent — who counts them and
reports "600 jobs" has published a capability claim nobody made. The second failure is the
mirror of it: a coverage row that cites no canonical job, so nobody can tell which desired job
it is a claim about.

## Approaches considered

**A — one file.** Add `coverage` and `roadmap` fields to the catalogue records themselves.
Rejected: the catalogue is a portable desired-state corpus, frozen and hash-verified by
`docs/jtbd/tools/verify_catalog.py`. Writing repository conclusions into it destroys the one
property that makes it useful — that it says nothing about this repository — and it puts
desire, evidence and priority in one vocabulary, which is the failure above rather than a fix
for it.

**B — a generated matrix.** Regenerate `CRM_JTBD_MATRIX.md` from the catalogue plus an overlay.
Rejected **for v1**, not on principle: ADR-039 `JTBD_ROWS_NOT_ENCODED` holds that no job status
is a generated fact, and 149 hand-written rows carrying evidence, scope notes and anti-inflation
paragraphs cannot be regenerated without losing the part a person wrote. Recorded as the v2
plan in `docs/jtbd/coverage/MATRIX_CROSSWALK.md`, gated on the crosswalk being complete first.

**C — three separate overlay layers, joined by id (chosen).** The catalogue stays frozen. A
coverage overlay and a roadmap-ownership overlay sit beside it in their own files, in their own
vocabularies, joined only by `jtbd_id`. A crosswalk maps every existing matrix row onto canonical
ids. A checker refuses the ways they can drift. Chosen because it is the only option where
"this job is desired", "this job is proven" and "this job is planned" cannot be confused by
reading one field, and because each layer can be regenerated or hand-reviewed independently.

**D — extend the Repository Truth Contract to hold per-JTBD facts.** Rejected: 600 facts in
`docs/repository-truth.json` would make every catalogue edit a truth-document regeneration, and
ADR-039 already refuses per-row encoding. Only six narrow *summary* facts are added, all
generated by counting, none typed.

## What is built

| Layer | File | Vocabulary |
|---|---|---|
| 1 desired | `docs/jtbd/catalog/**` (**unchanged**) | catalogue's own `NOT_ASSESSED…PRODUCTION_READY` |
| 2 coverage | `docs/jtbd/coverage/coverage.overlay.jsonl` | the four in `docs/QUALITY_GATES.md` §3 |
| 3 ownership | `docs/jtbd/roadmap/roadmap.overlay.jsonl` | `implemented\|in progress\|planned\|deferred\|unassigned\|out of scope` |

Inputs a person writes, and the generator only reads:

- `docs/jtbd/coverage/assessments.json` — the **only** place a positive coverage status can be
  born. Each entry carries evidence paths with their content digests, limitations, a
  `verifiedAtSha` and Repository Truth fact ids.
- `docs/jtbd/roadmap/capability_pillars.json` — 225 catalogue capabilities → one Accordo pillar.
- `docs/jtbd/roadmap/pillars.json` — the pillar registry: edition, track, milestone, dependencies.
- `docs/jtbd/coverage/matrix_crosswalk.json` — every `CRM_JTBD_MATRIX.md` row → disposition
  and canonical ids.

Generator and gate: `scripts/jtbd-gate.js` (`--write` regenerates the two overlays; default
checks). It is Node, not Python, because it has to run inside `npm run verify`, and nothing in
this repository's CI depends on a Python interpreter. The catalogue tools stay Python because
they are the agent-facing slice tools and already are.

Six summary facts join the Repository Truth Contract under a new `jtbd.portfolio` source
authority. All six are counted, never typed.

## What v1 deliberately does not do

- It does not move the matrix to a generated view. It records what that would take.
- It does not promote any row automatically. `--write` cannot invent a positive status; it can
  only copy one out of `assessments.json`.
- It publishes no priority, business value or competitive rationale in any public overlay.
- It adds no product command, no rail and nothing to `npm run surface:check`'s budget.
