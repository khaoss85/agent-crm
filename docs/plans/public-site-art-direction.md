# Public site art direction, motion and interaction pass

## Goal and user-visible outcome

Make the repository-controlled public site feel distinctive, alive and product-led while preserving its accepted information architecture, claim/evidence contracts, generated Markdown peers, SEO, canonical URLs and product/repository-truth separation. A new visitor should first notice the experience, then understand that Accordo is a custom CRM framework for coding agents, then see why deterministic policy and human authority make it different.

## Current repository context

- Inspected branch `work` at `3db700897367bd4bccaec7e838327ee45c8e0d9c`; production `version.json` reports that exact commit on `main`, generated by Vercel, with measurements bound to `cc2a1a6`.
- `site/templates/index.html` already carries the accepted human journey and the discount-approval line, but the visual treatment is mostly static grids of similarly bordered rectangles.
- `site/assets/styles.css` owns the zero-dependency visual system. The production CSP intentionally has no `script-src`, so the chosen motion design must work with CSS and semantic HTML rather than introducing a site runtime.
- `scripts/site-build.js` generates HTML, Markdown peers, structured data and discovery files from the same templates and ledgers. Visual changes must leave that machinery intact.
- `scripts/site-shots.js` is the existing browser receipt path, but its target list is too narrow for this visual acceptance scope.
- Human pages in scope are Home, Product, Solutions and four solution stories, How It Works, Product Proof, For AI Agents, Developers and Resources. Retrieval/evidence pages retain their formal tone and generated structure.
- Baseline `npm install` completed. Baseline `npm run verify` cannot complete in this container because it supplies Node 20.20.2 while the project requires Node >=22.16.0 and the suite imports `node:sqlite`; this is an environment limitation, not a branch regression.

## Approaches considered

1. **Add a JavaScript animation framework.** This could deliver elaborate scroll choreography, but it violates the standard-library-first posture, expands the bundle and CSP, weakens no-script behavior, and adds a production dependency for effects CSS can express. Rejected.
2. **Create image- or video-led hero art.** This could make a strong first frame, but the core product explanation and state transitions would become opaque to machines, reduced-motion users and slow connections. It would also make semantic color and responsive behavior harder to maintain. Rejected.
3. **Build a CSS/SVG/HTML-native “Flow” system.** Use semantic text, ordered lists, pseudo-elements, CSS custom properties, keyframes and view-timeline-enhanced progressive motion with static fallbacks. This preserves the CSP and machine discovery, keeps bundle impact small, and lets the same product metaphor adapt across pages. Chosen.

## Milestones

### 1. Establish the visual language

- Replace the conservative neutral/green layer with warm canvas, ink, flow green, agent violet, human coral, pending yellow and data cyan tokens.
- Establish expressive display typography with reliable system stacks, readable body typography and monospace limited to technical labels/evidence.
- Define five coherent motion layers: hero choreography, ambient rail, scroll-enhanced Flow, microinteractions and section entrances, all disabled by `prefers-reduced-motion`.

### 2. Make the homepage tell the product story

- Reduce the hero to one memorable promise, one short explanation and two CTAs.
- Turn the existing discount boundary into an animated semantic demonstration: agent proposal, policy block, human approval, continuation and audit evidence.
- Thread the lifecycle Flow through the page and vary editorial rhythm instead of repeating card grids.

### 3. Carry the language through accepted journeys

- Give Product, How It Works and Product Proof distinct Flow/proof compositions.
- Open each solution page with a concrete business scenario and a page-specific flow, while retaining proof, limitation and start paths.
- Keep Developers and For AI Agents technical but concise; improve Resources and Solutions navigation affordance without changing destinations.

### 4. Audit affordance and browser behavior

- Mark navigational collections as whole semantic anchors with consistent arrows and hover/focus/tap feedback.
- Keep informational surfaces visually still and free of link-like elevation/cursors; interactive disclosure remains native `details`/`summary` with explicit state affordance.
- Extend browser receipts to every requested page plus 390px Home, and inspect desktop, mobile and reduced-motion output.
- Add focused regression coverage for key navigational-card and semantic Flow contracts.

### 5. Validate and document the outcome

- Run site, SEO, Markdown/llms, repository-truth, CSP/accessibility-oriented and full repository gates.
- Update this plan with results, decisions, screenshots inspected, performance impact and residual limitations.

## Decision log

- Preserve the no-script production CSP. Motion will be CSS-native and ornamental enhancement; all meaning remains present in HTML at rest.
- Treat “The Flow” as a state-and-authority language, not a decorative pipeline: violet is agent input, green is policy/valid flow, coral is a human decision, yellow is pending/blocked and cyan is data/evidence.
- Do not edit claim strings or evidence records. Human microcopy may frame them, but generated repository truth stays exact.

## Outcome and follow-up

The repository-controlled site now has a distinctive, semantic Flow language and scenario-led human surfaces without changing URLs, IA, ledgers, generated Markdown, discovery assets or runtime code. The pass adds no production bytes outside HTML and CSS and no network request. Browser receipts show the hero remains legible at 390px, the discount sequence converts to a vertical path, and forced reduced motion exposes every state immediately.

Residual limitations: scroll-linked section entrances are progressive enhancement and therefore absent in browsers without view-timeline support; the script-free CSP rules out user-controlled replay of the automatic hero sequence; and browser automation remains a manually invoked repository receipt rather than a CI gate. The repository-wide suite should be allowed to finish in the normal Node 22 CI environment before merge.
