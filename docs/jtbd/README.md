# Accordo JTBD desired-state catalog

This directory contains the **real source artifact** used to audit Accordo against a broad CRM/CDP/agentic-CRM jobs-to-be-done model.

Catalog version: `2026-08-20.1`  
Scope: **30 personas · 600 JTBD (20 each) · 225 capabilities · 10 end-to-end scenarios**.

## Truth boundary

This is a **desired-state requirements catalog**, not a statement of what Accordo currently supports. Every embedded catalog coverage record starts at `NOT_ASSESSED`. Repository coverage must be assessed against a pinned SHA and must use the four-value status vocabulary in `docs/QUALITY_GATES.md`. Read `coverage/STATUS_CROSSWALK.md` before Phase D.

## Canonical storage and ordinary-file view

The exact original corpus is checked in under `source/` as lossless XZ data. The transport representation is compressed because the connector used for this publication cannot reliably send the 4.6 MB JSONL as one contents-API payload. `manifest.json` pins byte lengths and SHA-256 for both compressed and decompressed forms.

Nothing is summarized or regenerated by an LLM. Python's standard-library XZ decompression reconstructs the original bytes exactly.

Validate the checked-in corpus without writing generated files:

```bash
python docs/jtbd/tools/verify_catalog.py
```

Query it directly, without materializing:

```bash
python docs/jtbd/tools/query_catalog.py --role "Sales Manager"
python docs/jtbd/tools/query_catalog.py --id ACC-JTBD-CRO-001 --json
python docs/jtbd/tools/query_catalog.py --capability AIA-001
```

When a workflow expects the ordinary paths, run:

```bash
python docs/jtbd/tools/materialize_catalog.py
```

That creates, byte-for-byte:

- `docs/jtbd/catalog/jtbd.jsonl` — 4,611,152 bytes, 600 JSONL records;
- `docs/jtbd/MASTER.md` — 370,072 bytes;
- `docs/jtbd/catalog/personas.json`;
- `docs/jtbd/catalog/capabilities.json`;
- `docs/jtbd/catalog/e2e_scenarios.json`.

Those materialized paths are ignored derived working-tree views. The committed canonical sources are `source/*.xz` plus `manifest.json`.

## Phase D workflow

1. Pin repository SHA and record runtime/test constraints.
2. Run `verify_catalog.py`.
3. Read root `AGENTS.md`, `docs/QUALITY_GATES.md`, this `AGENTS.md`, and `coverage/STATUS_CROSSWALK.md`.
4. Select JTBDs with `query_catalog.py` or materialize the ordinary files.
5. Use the smallest Accordo rail that proves the question. Do not infer support from source/prose.
6. Bind exact evidence and residual limitations to the repository overlay.
7. Only after the audit, convert demonstrated gaps into roadmap candidates.

`prompts/` contains operational templates for audit, roadmap, specification, competitor research and lifecycle simulation. Where any package instruction conflicts with repository governance, root repository rules win.
