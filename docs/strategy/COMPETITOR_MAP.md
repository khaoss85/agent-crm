## What changed since August 4, 2026 *(re-checked 2026-08-20)*

Four things, in descending order of how much they should worry us.

1. **Comp AI CRM stopped being a manifesto.** The August 4 row called it "81 commits … a thesis demo, not infrastructure". It is now 211 commits, 8.7k stars, 1.0k forks — and, more importantly, it now ships the *exact* agent-facing repository surface this project has been treating as its differentiator: `AGENTS.md`, `CLAUDE.md`, `.claude/`, `.agents/skills/`, `skills-lock.json` and `adrs/`. It also ships working authentication (Better Auth, Google/Microsoft/own IdP), a durable scheduler, and live third-party providers — three things this framework does not have at all. See the row and the prose below.
2. **Salesforce announced the platform-scale version of our thesis** at TDX 2026 (April 2026): Headless 360, making the platform reachable by API, MCP and CLI without a browser, explicitly targeting Claude Code, Cursor, Codex and Windsurf. No number in that announcement could be verified from a primary source here.
3. **`cluster-software/agent-crm` exists**, is a16z-speedrun-backed, positions itself as "the headless CRM for Claude & Codex", and occupies the same repository *name* as ours. Its public repo is now a pointer to a monorepo we cannot see.
4. **Twenty and Relaticle both grew**, undramatically: Twenty 54.3k → 55.2k stars, Relaticle 30 → 32 MCP tools and 167 → 169 forks. Neither changed shape.

What did **not** change: nothing in this refresh moved any of this project's own boundaries. There is still no authentication ships, and a deployment must supply the verifier (L-01); persistence is still SQLite only (L-02); there is still no scheduler, so nothing runs unattended (L-04); every provider is still an offline fixture, with no email or calendar adapter that sends anything to anyone (L-05); and the build benchmark has still **never been run** (L-03), so this file contains no Successful Agent Build Rate for this framework and cannot contain one.

Rows not listed above — Frappe CRM, EspoCRM/SuiteCRM, Odoo, Atomic CRM/Refine/Supabase starters, DIY, Salesforce (other than Headless 360), HubSpot — were **not** re-verified on 2026-08-20 and remain as recorded on their original check dates.

## Strengths and weaknesses in prose

**Twenty** *(figures re-checked 2026-08-20; the analysis is unchanged from August 4)* — *Strengths*: category leadership (55.2k stars and 8.6k forks as of 2026-08-20, up from 54.3k stars; YC S23, ~$5.5M raised — [Crunchbase](https://www.crunchbase.com/organization/twenty-6919), [tech.eu](https://tech.eu/2024/11/19/twenty-secures-5m-to-challenge-crm-giants-with-open-source/)), real product velocity (weekly releases), and since 2.0 a genuinely good code-first story: MIT SDK, `create-twenty-app`, git-backed workspace versioning, native MCP, in-product agents. *Weaknesses*: everything runs inside their platform runtime — the agent writes extensions against their abstractions, never owns the application; AGPL + enterprise-gated files (SSO, advanced RBAC) reintroduce exactly the lock-in the open-source pitch disclaims; self-host upgrade fragility documented ([issue #14705](https://github.com/twentyhq/twenty/issues/14705)). **This is the strongest competitive threat**, and the threat is narrative convergence more than product overlap.

**Frappe CRM** — *Strengths*: the most mature metadata-driven customization model in OSS; huge ERPNext adjacency; managed cloud. *Weaknesses*: Python/MariaDB stack outside the coding-agent mainstream; customization lives as metadata in a running database — the worst possible shape for a coding agent (no diffs, no review, no tests); AI story entirely third-party. The community's demand for MCP-with-permissions-and-audit ([frappe#33170](https://github.com/frappe/frappe/issues/33170)) is evidence for *our* governance thesis.

**Relaticle** *(figures re-checked 2026-08-20; the analysis is unchanged from August 4)* — *Strengths*: first-mover on "agent-native CRM" language with a real MCP server, now advertised at **32 tools** (up from 30 on 2026-08-04); modern PHP. *Weaknesses*: agents can operate but not reshape it; runtime config, fixed app; AGPL; solo-maintainer scale. It defines the adjacent category ("AI agents in a CRM") we must not be confused with.

**Comp AI CRM** *(re-checked 2026-08-20 — this paragraph is materially rewritten)* — The August 4 verdict ("a manifesto, not a platform") **no longer holds, and we should stop repeating it.** Commits went 81 → 211, stars 4.4k → 8.7k, and forks are now 1.0k — a fork/star ratio around 0.12, which is weak, but it is no longer only stars. *Strengths, stated plainly because several of them are places it is simply ahead of us*: it now ships the agent-facing repository surface this project has been calling its differentiator — `AGENTS.md`, `CLAUDE.md`, `.claude/`, `.agents/skills/` (41 skill directories) and, notably, `skills-lock.json`, which pins 23 third-party skills by source, path and SHA-256 hash. **We do not have a skills lockfile; they do, and content-hash-pinning an agent's skill set is a good idea we did not have first.** Beyond the agent surface it ships three capabilities we do not have at all: **authentication** that works (Better Auth; "Google, Microsoft, or your own IdP" with an allow-list) against our none (L-01); a **durable scheduler** — Vercel's `eve`, sessions that "survive a redeploy", cron dispatch and `FOR UPDATE SKIP LOCKED` leasing — against our none, since nothing here runs unattended (L-04); and **live providers** (Gmail via Google OAuth, Google Calendar, Context enrichment, optional Perplexity) against our offline fixtures, where "no adapter sends anything to anyone" (L-05). It also runs on Postgres where we are SQLite-only (L-02). *Weaknesses, which are still real*: no MCP at all (no `mcp` package; unmentioned in README and `docs/agent.md`); fixed schema; single-tenant as a stated design choice, not an oversight — "There are no organizations. **Salesforce Headless 360** *(added 2026-08-20)* — At TDX 2026 (April 2026) Salesforce announced that its platform is reachable by API, MCP tool and CLI command with no browser and no UI, aimed by name at Claude Code, Cursor, Codex and Windsurf. Read carefully, this is *not* our thesis: it makes their runtime callable by a coding agent, it does not hand the customer owned code — Apex and metadata still execute only on their platform, and the row above records that. But it is the strongest possible validation that "the coding agent is the user" is now a mainstream architectural position rather than a bet, and it removes "incumbents cannot reach coding agents" from our list of durable advantages. The competitive consequence is narrow and specific: our differentiator cannot be *access* (Salesforce now has more of it than we do) and cannot be *tool count* (they will always win that). It has to be **ownership** — code in the customer's repository, under a permissive licence, that runs without them. *What we could not verify*: any number. ## The gap this project can realistically own

Across the researched set, as of August 4, 2026, no direct equivalent was found for: **a permissively-licensed Node/TypeScript-ecosystem framework where the coding agent generates a bespoke CRM as reviewable, owned code — with deterministic workflows, human-approval policy, audit and trace as framework primitives, and MCP/skills as first-class surfaces.** This is a statement about the researched set, not proof the market is empty; unresearched or future entrants (Twenty above all) may occupy it.

**Revision, 2026-08-20.** That sentence still holds as written — nothing found on this refresh generates a bespoke CRM as owned code — but **half of it has stopped being distinctive**, and the file should say so rather than keep quoting the whole sentence as a moat. "MCP/skills as first-class surfaces" is now table stakes: Comp AI ships `AGENTS.md`, `CLAUDE.md`, `.claude/`, `.agents/skills/` and a hash-pinned `skills-lock.json`; `cluster-software/agent-crm` ships `AGENTS.md` and `CLAUDE.md`; Relaticle advertises 32 MCP tools; Salesforce has announced an MCP/CLI-addressable platform aimed at Claude Code by name. An agent-facing repository surface is a weekend of work, and in the last sixteen days the most-starred project in this category did it.

What survives as genuinely unoccupied is narrower and should be stated narrowly: **the coding agent generates the CRM as code the customer owns and can run without us, with deterministic workflow, versioned commercial policy, an approval that a non-human actor is refused, and audit plus trace as framework primitives.** Not the files. Not the tool count. The refusal and the trace. Nothing in the refreshed set shows that combination — but note this is again a statement about the researched set, and that it is a claim about *design*, not about *proof*: **the build benchmark has never been run, so this framework has no success-rate figure of any kind and none may be quoted.**

Convergent evidence it is real and reachable: (1) incumbents' metadata-customization is architecturally opposed to coding-agent strengths, and none can pivot to code generation without abandoning their platform economics — though Salesforce Headless 360 shows they can get much closer than we assumed on August 4 without pivoting at all; (2) demand signals exist on every edge of the square — Frappe users asking for governed MCP, Comp AI's star spike, Atomic CRM's fork behavior, Twenty's own pivot toward "CRM as code", and now a16z funding a headless CRM aimed squarely at Claude; (3) micro-projects (Atlas Headless CRM's auto-generated MCP tools from entity config, Attri's evidence-chain concept — now shipped as `Attri-Inc/open-tooling`, though dormant since March 2026 at 7 stars) keep independently reinventing pieces of it at ≤10 stars — the ideas are in the air, the execution seat is open.

Structural risks, stated honestly and revised on 2026-08-20:

1. **Twenty could extend its MIT SDK layer downward into true code ownership faster than we can build distribution.** Unchanged from August 4, and still the largest *narrative* threat at 55.2k stars.
2. **The incumbents own the end-buyer relationships**, so we must win *builders* (developers and their agents), not CRM shoppers. Unchanged — and Headless 360 makes it worse, because those buyers can now point a coding agent at the CRM they already have.
3. **New: capability gap, not narrative gap.** Comp AI ships authentication, a durable scheduler and live providers; we ship none of the three (L-01, L-04, offline fixtures) and persist to SQLite only (L-02). Any comparison we publish must lead with that, because a reader who installs both will find it in ten minutes. Feature breadth is not the answer, but the honest framing is: this is a framework for generating an application, not an application — and that only stays credible while the generated application is demonstrably better than what a developer would otherwise hand-write.
4. **New: name collision.** `cluster-software/agent-crm` holds the same repository name with a16z backing and the `@agent-crm/*` npm scope. This is a distribution and discovery problem before it is a product one (`BRAND_REQUIREMENTS.md`, `AGENT_DISCOVERY.md`).

Risks 1, 2 and 3 are addressed by speed on the benchmark + agent-surface moats (`EXECUTION_ROADMAP.md` Phases 8–12) rather than feature breadth — with the caveat that the benchmark, the thing this plan rests on, has not yet produced a single measurement.
