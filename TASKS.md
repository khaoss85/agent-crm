- [x] **Production Spine v1 — verified identity, one tenant per instance, authorization (ADR-038).** The runtime stops trusting the caller. Before it, `normalizeActor()` returned `SYSTEM_ACTOR` for `null`, a string or an unknown type — the safest input produced the strongest identity — `actorFromRequest()` invented `{type: 'user', id: 'api-user'}` from missing headers, and no record carried a tenant. The decision is **the framework authenticates nobody and owns everything after that**: a deployment adapter verifies the request and supplies a bounded `IDENTITY_CONTRACT = 1` context in four kinds that never blur (`verified-user`, `system`, `asserted-local`, `anonymous`), carrying a fingerprint of the claims and never a token or secret. The framework owns tenant selection, membership, the authorization decision over eleven bounded permissions in five role bundles, the audit evidence, and a fail-closed boundary ordered 401 → 404 → 403. `ACCORDO_MODE` has **no default** — an unset mode is an error — and production **fails startup** without a verifier and a tenant strategy. Tenancy is **one tenant per application instance, enforced rather than described**: the storage handle has no `databasePathFor`, so a second tenant is unreachable rather than refused; control and data planes are separate files with separate migration lists. **This is not shared-database multi-tenancy**, row-level tenancy over 86+ tables was deliberately not attempted, and an Accordo Organization is not a CRM Company. `requiredApprovalKey` values stay descriptive labels, because enforcing them would change the meaning of records already written. `PRODUCTION_SPINE_ABSENT` was **narrowed, never deleted** (PR #98).
